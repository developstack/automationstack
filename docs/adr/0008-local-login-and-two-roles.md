# 只使用本地登录，平台角色只有管理员和普通用户

以前，平台可以用 Casdoor 登录，平台角色有三个：平台管理员、项目管理员和普通用户。项目内还有两个角色：项目 owner 和项目成员。这些规则太复杂：用户不知道谁可以添加成员，也不知道为什么不能添加。部署也要多维护一个 Casdoor。所以我们删除 Casdoor，只保留本地登录，并把角色减少为两个。

现在的规则如下：

- 用户用平台保存的用户名和密码登录。
- 平台角色只有管理员和普通用户。
- 只有管理员可以新建项目、管理用户、管理项目成员、修改项目和平台设置。
- 项目内没有角色。普通用户只能进入自己加入的项目。
- 测试任务的创建者和管理员可以作废测试任务。

迁移 `0023_local_auth_two_roles` 删除认证设置表、`users.auth_source` 列和 `project_members.role` 列。原来的项目管理员改为管理员。以前的 Casdoor 账号保留，它们没有密码。

## Considered Options

- **保留 Casdoor，只修复界面提示**：这个方案被拒绝。问题的原因是规则太多，不是提示太少。
- **普通用户可以新建项目，并管理自己的项目**：这个方案被拒绝。这样项目内必须保留拥有者角色，又回到原来的问题。
- **删除以前的 Casdoor 账号**：这个方案被拒绝。这些账号创建的用例和测试记录会失去作者。

## Consequences

- 没有密码的账号不能登录。它们的旧会话和 API token 也失效。管理员在「用户」页面重置密码后，这些账号才能使用。
- `users.external_id` 列保留。删除这一列之前必须得到确认。
- 以前的 Casdoor 对账任务的定时计划在启动时删除。
