# 测试任务中的用例记录自己的模块

以前，测试任务不记录用例的模块。测试任务页面和测试报告读取用例现在的模块。用户把用例移到另一个模块后，所有测试任务中的这条用例都显示新的模块，已完成的测试任务也改变。已完成的测试报告必须保持完成时的样子，所以我们让测试任务中的用例记录自己的模块。

现在的规则如下：

- `test_run_cases.module_id` 记录用例在这个测试任务中的模块。用例加入测试任务时，服务端写入用例当时的模块。
- 用例移到另一个模块时，进行中的测试任务（待评审、待测试、测试中）中这条用例的模块也改变。
- 已完成、已提交和已作废的测试任务不改变。
- 页面上批量移动用例时，如果有进行中的测试任务会改变，页面先列出这些测试任务，用户确认后才移动。
- 单条移动、脑图中的移动和 MCP 的 `move_cases` 使用同一条规则。

迁移 `0024_run_case_module` 增加这一列，并把已有的行设为用例现在的模块。这一列为 null（模块已删除）时，服务端使用用例现在的模块。

## Considered Options

- **测试任务完成时才记录模块**：这个方案被拒绝。已完成的测试任务可以回到测试中，这时记录的模块必须清除。规则更复杂。
- **所有测试任务都读取用例现在的模块**：这个方案被拒绝。已完成的测试报告会在完成后改变。

## Consequences

- 迁移以前，已经有用例移动过的测试任务不能恢复原来的模块。迁移把这些测试任务设为用例现在的模块。
- 模块改名时，所有测试任务显示新的名称。记录的是模块，不是模块名称。
- 只调整排序的写入不改变用例的更新时间。用例列表按更新时间降序排列，所以其他用例的位置变化不会把它们排到最前面。
