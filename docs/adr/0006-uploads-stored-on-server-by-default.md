# 上传的文件默认存储在服务器本地，R2 是可选项

以前，用例图片和执行页附件只能存储在 Cloudflare R2 中。没有 R2 配置时，上传功能不可用。单机部署在阿里云的服务器上，我们不想为它申请 R2。所以我们增加服务器本地存储，并把它作为默认的存储方式。

平台管理员在「存储设置」页面中选择存储方式：服务器本地或 Cloudflare R2。R2 的配置也在这个页面中填写，Secret Access Key 用 `SECRET_ENCRYPTION_KEY` 加密后存入数据库。页面没有保存过时，服务使用环境变量：`R2_*` 完整则使用 R2，否则使用服务器本地。所以 k8s 上的部署不需要修改。

本地存储使用与 R2 相同的上传方式：服务端签发地址，客户端用 PUT 上传文件。所以前端、MCP 和三种 SDK 都不需要修改。下载地址由服务端用 `SESSION_SECRET` 签名。用例图片的下载地址不会过期，所以浏览器可以缓存它，安全性与 ADR-0003 的公开链接相同。执行页附件的下载地址有过期时间。服务端检查签名后，用 `X-Accel-Redirect` 让 nginx 发送文件。

## Considered Options

- **每个附件记录它的存储方式**：这个方案被拒绝。它需要修改所有附件表。我们的做法是：读取时先查本地目录，本地没有这个对象时使用 R2。所以切换存储方式后，以前的文件仍然可以查看，不需要迁移。
- **nginx 用 secure_link 检查签名**：这个方案被拒绝。没有 nginx 的部署（本地开发、k8s）也必须能下载文件，所以签名只由服务端检查。

## Consequences

- 本地存储只能用于一个 server 实例，或者所有实例共用同一个目录。k8s 上的部署没有共用的目录，所以必须使用 R2。
- 本地目录中的文件不在数据库备份中。必须单独备份这个目录。
- 更换 `SESSION_SECRET` 后，以前签发的本地下载地址失效。页面重新加载后，服务端签发新的地址。
