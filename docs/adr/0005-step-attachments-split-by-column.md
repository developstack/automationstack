# 截图按栏分组，人工的实际附件挂在步骤上，自动化附件挂在用例上

一个用例步骤原来只有一组步骤截图。用户分不清一张截图属于操作还是预期结果。我们把截图分成两组：操作截图和预期截图。在测试任务中，每个步骤记录实际结果，实际结果由文字和实际附件组成。

人工上传的实际附件挂在步骤上。自动化上传的附件仍然挂在整条用例上，因为自动化脚本通常不知道失败发生在哪一步。界面上不再提供整条用例的附件区。

已有的步骤截图全部删除，没有迁移。数据库迁移删除当前步骤和历史版本中的截图引用，以及对应的附件记录。R2 中的文件由一个清理脚本删除，由人手动执行。

## Considered Options

- **每张截图标记属于哪一栏**：这个方案被拒绝。两组列表更容易理解，也更容易限制数量。
- **把已有截图迁移到操作截图**：这个方案被拒绝。我们不知道一张旧截图属于操作还是预期结果，猜错比删除更糟。
- **自动化上传也必须指定步骤**：这个方案被拒绝。它会使现有的自动化接入失效。

## Consequences

- 版本历史中不再显示旧截图。
- 测试任务中原来人工上传到整条用例的附件，在原位置只读显示，不能再上传新的。
- MCP 读取用例时不返回截图。MCP 写入截图时，先取得上传地址，再上传文件，最后在步骤中引用这次上传。
