# 用例操作记录在用例删除后仍然保留

项目概览增加两张卡片：「成员工作量」和「操作日志」。「成员工作量」显示每个成员新建的用例数。「操作日志」显示谁在什么时候修改或删除了哪条用例。

以前，用例版本是唯一的历史记录。用例删除时，版本也一起删除，所以删除没有记录。版本只记录保存人的用户名，不记录用户 id。

现在的规则如下：

- 用例版本增加 `saved_by_id`，记录保存人的用户 id。迁移 0026 按用户名补填已有的版本。用户名对不上的版本保持为空。
- 新表 `case_activities` 记录每条用例的新建、修改和删除。服务端在写入用例的同一个事务中写入记录。
- 记录中的 `case_id` 和 `module_id` 不是外键。用例或模块删除后，记录仍然保留。记录保存用例名称、版本、修改说明和操作人。
- 写入一个用例版本时，服务端写入一条记录：版本 1 是新建，其他版本是修改。没有改变内容的写入不生成版本，也没有记录。
- 删除一条用例、批量删除用例和删除模块时，服务端为每条删除的用例写入一条记录。删除项目时不写入记录，因为项目的记录一起删除。
- 移动和排序不生成版本，所以没有记录。
- `created_at` 是事务开始的时间。一次批量操作的记录有相同的 `created_at`，「操作日志」按操作人、操作和时间把它们合成一条。
- 迁移 0026 从已有的版本写入记录。已经删除的用例没有版本，所以没有记录。

## Considered Options

- **从用例版本读取历史**：这个方案被拒绝。用例删除后，版本也被删除，新建的用例数会变少，删除也没有记录。
- **软删除用例**：这个方案被拒绝。所有读取用例的查询都要排除已删除的用例，改动太大。
- **为每次批量操作写入批次 id**：这个方案被拒绝。所有写入路径都要传递批次 id。同一个事务中 `now()` 的值相同，所以 `created_at` 已经可以区分批次。

## Consequences

- `case_activities` 与用例版本有重复的数据。用例版本用于查看和回滚，操作记录用于统计和日志。
- 每个写入用例的路径都必须传入操作人的用户 id。
- `case_activities` 不会自动清理。
