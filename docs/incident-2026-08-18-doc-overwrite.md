- 日期：2026-08-18
- 严重级别：数据丢失（单个未入库文档，内容不可恢复）
- 责任方：主 agent（Claude，第一期实施的编排者）

## 事故经过

1. 用户指示主 agent：「把 plan 保存下来，先设置一下 docs/init-code-quantity.md，然后再开始 plan、分配任务给子 agent」。
2. 主 agent 将该指示误解为「把实施计划写入 docs/init-code-quantity.md」，实际上该文件是用户已有的项目初始化规范文档。
3. 主 agent 直接用 Write（整文件覆盖）写入了自己的实施计划，**覆盖前未读取该文件的既有内容**。
4. 用户随后询问「按照 docs/init-code-quantity.md 初始化项目了吗？」并发现文档被改，指出错误。

## 影响

- 用户的原始文档内容全部丢失。该文件未被 git 跟踪（仓库仅有 initial commit，docs/ 目录处于 untracked 状态），无任何版本可回退。
- 恢复尝试均失败：git 历史/stash 无记录；`tmutil listlocalsnapshots /` 无本地 Time Machine 快照；废纸篓无副本；主 agent 覆盖前未读过文件，上下文中亦无内容副本。
- 次生影响：原文档可能包含项目初始化的规范要求，W1 开发任务（数据库 schema、UI 基座）在未对照该规范的情况下进行，需在内容补回后重新核对。

## 根因分析

- **直接原因**：覆盖已有文件前未先读取确认内容——违反了「写前必读、覆盖前核查目标」的基本操作准则。
- **诱因**：
  - 用户指令存在歧义（「保存 plan」+「设置一下该文档」），主 agent 在有现成信号（Write 返回 "updated successfully" 而非 "created"，说明文件已存在）的情况下未察觉异常。
  - 该文件未入 git，缺少版本保护，单次误写即不可逆。

## 已执行的补救

1. 主 agent 的实施计划已移至独立文件 `docs/phase1-testcase-platform-plan.md`，`docs/init-code-quantity.md` 路径已空出，等待用户恢复原始内容。
2. 已向用户请求原文档内容（或要点复述），补回后将作为最高优先级基准，逐条核对已产出及后续所有代码。
3. **后续（2026-08-18）**：用户已自行恢复 `docs/init-code-quantity.md` 全文，并指示按该规范初始化项目的代码质量基建。该文档自此为编码规则的最高基准。

## 纠正与预防措施

1. **写前必读**：任何对非自建文件的 Write/覆盖操作，必须先 Read 原内容；若发现目标文件已存在且内容非自己所写，停止操作并向用户确认。
2. **区分「保存我的输出」与「修改用户的文件」**：涉及用户既有文档的指令有歧义时，先澄清再动手；agent 自产文档一律使用独立的新文件名。
3. **尽早入库**：建议本仓库尽快将 docs/ 等重要目录纳入 git 提交节奏（哪怕是 WIP commit），使误写可回退。
4. **子 agent 派发约束**：任务书中已明确文件范围与「不得越界」条款，本条同样约束主 agent 自身。
