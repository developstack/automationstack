# 步骤截图的 R2 清理说明

本文说明怎样删除 R2 中旧的步骤截图对象。决定和原因见 `docs/adr/0005-step-attachments-split-by-column.md`。

## 1. 术语

| 术语 | 意义 |
| --- | --- |
| 步骤截图 | 旧功能。一个步骤有一组截图，截图是用例附件。迁移 0019 删除这个功能的数据。 |
| 对象键 | 对象在 bucket 中的名称。服务端在代码中把对象键叫作 `storageKey`。 |
| 清理队列 | 数据库表 `step_screenshot_purge`。每一行是迁移 0019 删除的一个附件记录和它的对象键。 |
| 清理脚本 | `scripts/purge-step-screenshots.ts`。清理脚本删除清理队列中的对象。 |
| 文字引用 | 文字中的 `![](attachment:<附件 id>)`。前置条件、操作步骤和预期结果用文字引用嵌入图片。 |

## 2. 工作方式

1. 部署时，迁移 0019 自动执行。
2. 迁移 0019 找到步骤截图引用的附件记录。
3. 迁移 0019 不删除有文字引用的附件记录。迁移检查用例、版本、测试任务和执行记录的每一行的所有列。
4. 迁移 0019 把其他附件记录的对象键复制到清理队列，然后删除这些附件记录。
5. 迁移 0019 从当前步骤和所有版本快照中删除 `screenshots` 字段。
6. 迁移 0019 不删除 R2 中的对象。你用清理脚本删除这些对象。

清理脚本只读取清理队列。清理脚本不扫描 bucket，所以它不删除清理队列以外的对象。

清理脚本有两种模式：

- 默认模式只列出对象键。这个模式不删除对象，也不修改数据库。
- `--apply` 模式删除对象。清理脚本删除一个对象后，从清理队列删除对应的行。中断后，你可以再次执行清理脚本。

如果一个附件记录仍然使用同一个对象键，清理脚本跳过这个对象，并显示一条警告。

## 3. 删除的后果

开始前，阅读本节。

- 删除的对象不能恢复。
- 旧版本的用例不显示这些截图，因为迁移 0019 删除了版本快照中的引用。
- 如果你配置了公开域名，Cloudflare 的边缘缓存和浏览器缓存可以继续保留已删除的图片。详细信息见 `docs/runbooks/image-cdn-setup.md`。

## 4. 准备条件

- 目标环境执行了迁移 0019。
- 你可以在服务端的 pod 中执行命令。
- 服务端的环境变量 `DATABASE_URL` 指向目标数据库。
- 服务端的 R2 环境变量指向目标 bucket。`--apply` 模式需要 R2 环境变量。默认模式不连接 R2。

## 5. 列出对象

1. 在服务端的 pod 中执行清理脚本，不加参数：

   ```bash
   kubectl exec -it deploy/<server> -- /app/apps/server/node_modules/.bin/tsx /app/scripts/purge-step-screenshots.ts
   ```

2. 检查输出。每一行是一个对象键。对象键以 `test-cases/` 开头。
3. 检查最后一行。最后一行显示列出、跳过的对象数量。
4. 如果输出中有「跳过」警告，停止。把警告发给开发人员。

在本地开发环境中，你可以执行 `pnpm r2:purge-step-screenshots`。

## 6. 删除对象

1. 完成第 5 节的步骤。
2. 在服务端的 pod 中执行清理脚本，加上 `--apply`：

   ```bash
   kubectl exec -it deploy/<server> -- /app/apps/server/node_modules/.bin/tsx /app/scripts/purge-step-screenshots.ts --apply
   ```

3. 检查最后一行。最后一行显示删除、失败和跳过的对象数量。
4. 如果失败数量大于 0，读取「删除失败」警告中的原因。
5. 修正原因。
6. 再次执行第 2 步。
7. 再次执行第 5 节的第 1 步。
8. 确认输出是「没有要删除的对象。」

如果失败数量大于 0，清理脚本的退出码是 1。

## 7. 完成后

1. 把第 6 节的输出发给开发人员。
2. 不要手动删除清理队列。清理队列为空后，开发人员在以后的迁移中删除 `step_screenshot_purge` 表。
